### 5 klaim paling berisiko bila dikutip di skripsi

1. **#75 teknologi:80, sandbox cap-drop ALL dan no-new-privileges untuk scanner dan aplikasi.** Risiko: container Semgrep, Trivy, dan audit dependency dijalankan dengan `docker run --rm` tanpa kedua flag itu (src/lib/scanner/run.ts:64-99); penguji yang membaca kode scanner bisa membantah klaim isolasi. Kalimat aman: "Container aplikasi hasil generate dijalankan dengan cap-drop ALL dan no-new-privileges; container pemindai dijalankan sekali pakai (--rm)."
2. **#44 README:203, provider dev aktif bila GitHub OAuth belum dikonfigurasi.** Risiko: anak kalimat "atau" menyiratkan akun dev bisa aktif di produksi; kode justru menolak melayani (HTTP 503). Kalimat aman: "Provider login dev hanya terdaftar saat NODE_ENV bukan production; di production tanpa GitHub OAuth aplikasi menolak melayani (HTTP 503)."
3. **#78b teknologi:130-131, CRUD proyek.** Risiko: /api/projects hanya punya POST dan /api/projects/[id] hanya PATCH; tidak ada handler GET atau DELETE proyek. Kalimat aman: "API proyek menyediakan pembuatan (POST) dan pembaruan (PATCH); data proyek dibaca oleh halaman server."
4. **#67 teknologi:64, default provider Google Gemini.** Risiko: fallback kode di src/lib/ai/resolve-model.ts:64-65 adalah `openai` dan `gpt-4o-mini`. Kalimat aman: "Nilai default dari .env.example adalah Gemini `gemini-flash-latest`; bila env tidak diisi, kode jatuh ke OpenAI `gpt-4o-mini`."
5. **#89 teknologi:266, 30+ sub-step.** Risiko: src/lib/stages.ts berisi 26 sub-step. Kalimat aman: "Lima tahap Secure SDLC dengan 26 sub-step berurutan."
